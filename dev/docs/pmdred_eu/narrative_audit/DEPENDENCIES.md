## 4. Assets personnages et portraits

Les cinématiques de donjon déclarent **28** identités d’acteur explicites. Une seule possède actuellement un override local Chara/Portrait détecté ; les autres dépendent des assets de base PMDO. L’absence d’override local n’est pas une absence de sprite, mais impose un probe runtime. Pour chaque acteur :

1. vérifier Idle/Walk/Run/Attack/Sleep/Hurt/pose spéciale utilisée ;
2. vérifier les directions et frames de retournement ;
3. vérifier toutes les émotions de portrait demandées ;
4. vérifier apparition, invisibilité, disparition et layering ;
5. vérifier l’échelle, l’ancre et l’ombre.

Liste machine : `narrative_scope.json → assets.actors`.

## 5. Musiques

- Identités PMD Red référencées : **59**.
- Correspondances New Era par normalisation exacte du nom : **14**.
- Sans correspondance exacte : **45**.
- Une similarité de nom ne prouve ni la bonne source audio, ni les loop points, ni le volume, ni le moment de déclenchement.

Chaque cue doit recevoir un mapping explicite `MUS_* → fichier PMDO`, un hash, des loop points et une timeline de start/fade/stop. Liste machine : `narrative_scope.json → assets.music`.

## 6. SFX, VFX et particules

- Construire un mapping exhaustif des IDs de fanfare/SFX GBA vers les assets PMDO ; New Era ne contient que 35 overrides Sound locaux.
- Traduire les `GroundEffectData`, opcodes bruts, flashes, couleurs de fond, fades et shakes en primitives PMDO mesurées.
- Valider visuellement alpha, position, durée, ordre des couches et frame d’apparition/disparition.
- `BossFX.lua` est une bibliothèque d’adaptation, pas une preuve d’équivalence PMD Red.

- interpréteur/IR des commandes Ground PMD Red ;

- caméra avec durée et easing mesurés ;
- système de portraits et variantes partenaire/héros ;
